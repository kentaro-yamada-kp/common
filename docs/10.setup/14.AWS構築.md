# AWS構築

## 概要

本番・検証用の共通EC2基盤（Amazon Linux 2023）の構築、Nginxの導入、およびLet's Encrypt（Certbot）を用いたSSL証明書の発行手順を説明します。
初期構築時に発生しやすいNginxのSSL証明書エラー (`BIO_new_file() failed (SSL: error:80000002:system library::No such file or directory)`) の原因と回避手順も含めて記載します。

## 目次

- AWS基盤と事前準備
- EC2インスタンスの作成とネットワーク設定
- Nginxのインストール
- Let's Encrypt (Certbot) によるSSL証明書発行
- よくあるエラーと対処法（証明書未存在エラー）
- 証明書の自動更新設定

## AWS基盤と事前準備

- **実行基盤**: Amazon Linux 2023 EC2インスタンス（1台）
- **リージョン**: `ap-northeast-1` (東京)
- **ドメイン**: `kykp.net` (および `www.kykp.net`)
- **固定IP**: Elastic IP (`GIP-1`) をアタッチ

## EC2インスタンスの作成とネットワーク設定

1. **インスタンス作成**
   - AMI: Amazon Linux 2023 AMI
   - インスタンスタイプ: 用途に応じたスペック（例: `t3.medium` 等、AIモデル推論や複数アプリ共存を考慮）
   - キーペア: `ec2-key-1`
2. **セキュリティグループ (Security Group)**
   - インバウンドルール:
     - SSH (Port 22): 管理元IP制限
     - HTTP (Port 80): 全世界 (0.0.0.0/0) - Let's Encrypt認証およびHTTP→HTTPSリダイレクト用
     - HTTPS (Port 443): 全世界 (0.0.0.0/0) - Webアクセス用
3. **Elastic IP**
   - Elastic IP を取得してインスタンスに紐付けます（例: `GIP-1`）。DNSのAレコードにこのElastic IPを設定します。

## Nginxのインストール

EC2へSSH接続し、Nginxをインストールします。

~~~bash
ssh -i secrets/ec2-key-1.pem ec2-user@kykp.net
sudo dnf update -y
sudo dnf install -y nginx
sudo systemctl enable --now nginx
~~~

## Let's Encrypt (Certbot) によるSSL証明書発行

Nginx上でHTTPS（Port 443）を有効化し、`jenkins/nginx.conf` を運用するには、あらかじめLet's EncryptのSSL証明書が発行されている必要があります。

### 1. Certbotのインストール
Amazon Linux 2023では、dnf経由でcertbotおよびnginxプラグインをインストールします。

~~~bash
sudo dnf install -y certbot python3-certbot-nginx
~~~

### 2. 証明書の発行 (Webroot方式 / Nginxプラグイン方式)
Nginxが起動している状態で、Webroot方式（`jenkins/nginx.conf` に含まれる `/.well-known/acme-challenge/` を利用）またはNginxプラグイン方式で証明書を発行します。

- **Nginxプラグイン方式の場合**:
  ~~~bash
  sudo certbot --nginx -d kykp.net -d www.kykp.net
  ~~~
- **Webroot方式の場合**:
  ~~~bash
  sudo mkdir -p /var/www/html/.well-known/acme-challenge
  sudo certbot certonly --webroot -w /var/www/html -d kykp.net -d www.kykp.net
  ~~~

発行が成功すると、以下のパスに証明書が生成されます。
- 証明書: `/etc/letsencrypt/live/kykp.net/fullchain.pem`
- 秘密鍵: `/etc/letsencrypt/live/kykp.net/privkey.pem`

## よくあるエラーと対処法（証明書未存在エラー・Webroot認証失敗）

### 1. 証明書未存在エラー (`BIO_new_file() failed`)
#### エラー内容
初回構築時や、まだSSL証明書が発行されていない状態で `jenkins/nginx.conf` （HTTPS設定を含む設定ファイル）を `/etc/nginx/conf.d/kykp.net.conf` として配置し、Nginxの構文テストやリロードを行うと、以下のエラーが発生してNginxが起動・リロードに失敗します。

```text
nginx: [emerg] cannot load certificate "/etc/letsencrypt/live/kykp.net/fullchain.pem": 
BIO_new_file() failed (SSL: error:80000002:system library::No such file or directory)
```

#### 原因
Nginxの設定ファイル（`conf.d/kykp.net.conf`）内の `ssl_certificate` および `ssl_certificate_key` ディレクティブが指定しているパスに、実際の証明書ファイル（`fullchain.pem` 等）が存在しないため（鶏と卵の問題）。

---

### 2. Webroot方式での認証失敗 (Unauthorized / HTML応答)
#### エラー内容
`sudo certbot certonly --webroot -w /var/www/html -d kykp.net -d www.kykp.net` を実行した際、以下のようなエラーになる場合があります。
```text
Type:   unauthorized
Detail: 52.198.26.26: Invalid response from http://kykp.net/.well-known/acme-challenge/...: "<!doctype html>\n<html lang=\"en\">\n..."
```

#### 原因
Let's Encryptの検証サーバーが `http://kykp.net/.well-known/acme-challenge/...` にアクセスした際、Nginxがチャレンジ用のファイル（`/var/www/html/.well-known/acme-challenge/...`）ではなく、フロントエンドアプリのインデックスHTML（`index.html`）やデフォルトのウェルカムページを返してしまっているため。これは、Nginxで `/.well-known/acme-challenge/` のルーティングが正しく機能していない、あるいはNginx設定が未読込／エラーでフォールバックしていることが原因です。

---

### 正しい初回構築・証明書発行の手順（推奨フロー）

上記のエラーを防ぐため、以下の順序で初期構築を行います。

1. **HTTP専用設定でのNginx起動**
   - 初回は、HTTPS（Port 443）の `server` ブロックを含まない（またはコメントアウトした）HTTP（Port 80）のみの設定ファイル（あるいは `jenkins/nginx.conf` のHTTPSブロックを一時的にコメントアウトしたもの）を `/etc/nginx/conf.d/kykp.net.conf` に配置します。
   - HTTPブロックには必ず以下のように `/.well-known/acme-challenge/` のルーティングを含めておきます。
     ```nginx
     server {
         listen 80;
         server_name kykp.net www.kykp.net;

         location /.well-known/acme-challenge/ {
             root /var/www/html;
         }

         location / {
             return 301 https://$host$request_uri;
         }
     }
     ```
   - 構文テストとリロードを行います。
     ```bash
     sudo nginx -t
     sudo systemctl reload nginx
     ```

2. **Certbotによる証明書発行**
   - ディレクトリを作成し、Webroot方式で証明書を発行します。
     ```bash
     sudo mkdir -p /var/www/html/.well-known/acme-challenge
     sudo certbot certonly --webroot -w /var/www/html -d kykp.net -d www.kykp.net
     ```
   - これにより `/etc/letsencrypt/live/kykp.net/fullchain.pem` および `privkey.pem` が生成されます。

3. **本番用Nginx設定（HTTPS対応）の配置と反映**
   - リポジトリの最新 `jenkins/nginx.conf` （最新の `http2 on;` 構文およびSSL証明書パスを含む）を `/etc/nginx/conf.d/kykp.net.conf` として配置します。
   - 再度構文テストとリロードを行います。
     ```bash
     sudo nginx -t
     sudo systemctl reload nginx
     ```

## 証明書の自動更新設定

Let's Encryptの証明書は90日間で有効期限が切れるため、自動更新の設定を行います。
Certbotインストール時に自動で設定されるsystemdタイマーを確認します。

~~~bash
# タイマーの状態確認
sudo systemctl status certbot-renew.timer

# 自動更新の設定
sudo systemctl enable --now certbot-renew.timer

# 自動更新のテスト（ドライラン）
sudo certbot renew --dry-run
~~~
